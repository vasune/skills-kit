# skills-kit

[![check](https://github.com/fhfqndj/skills-kit/actions/workflows/check.yml/badge.svg)](https://github.com/fhfqndj/skills-kit/actions/workflows/check.yml)

Универсальные навыки для AI-агентов: отобранные процессные практики, которые
работают в любом агентском harness и в любом проекте. Не полная библиотека
всех знаний, а ядро процессов — то, что не зависит от конкретного инструмента,
конкретного проекта и конкретной машины.

Навыки — обычные `SKILL.md` с YAML-frontmatter (формат Anthropic Agent Skills;
его читают Claude Code, Codex, opencode и другие совместимые агенты). Внутри навыка нет
никакого рантайма и скриптов установки: установка — это копия каталога навыка
в место, которое обходит ваш агент.

## Что здесь лежит

```text
skills-kit/
├── README.md            этот файл: критерии, формат, обслуживание
├── INDEX.md             каталог: что открывать под задачу
├── NOTICE.md            источники адаптированных методов и лицензии
├── LICENSE              MIT
├── plugin.json          манифест дистрибутива (автор — fhfqndj)
├── package.json         манифест пакета DeepSeek Harness (dsh.bundle.patch)
├── cordis.patch.yml     патч DSH: одна строка провайдера навыков
├── dsh-plugin.js        провайдер навыков для DSH: навыки из skills/ по запросу
├── Makefile             make check / test / pack / release
├── skills/              навыки, группа по смыслу
│   ├── core/            правила самой работы: план, делегирование, гигиена, мета-навыки
│   ├── git/             имена коммитов, ветки, PR, ревью, доступ агента к GitHub
│   └── code/            как писать, чинить и проверять код
├── subagents/           роли для делегирования
├── evals/               routing-кейсы для проверки триггеров
├── scripts/             check.py и сопутствующие инструменты
├── .claude-plugin/      манифесты для Claude Code
├── .codex-plugin/       манифест для Codex
└── .agents/             манифест для агент-хаба
```

Группа — это область работы, а не инструмент. Каталог
`skills/<группа>/<навык>/SKILL.md` — единственное место, где лежит навык.

## Критерии отбора

Навык попадает в ядро, только если верны все пять пунктов:

1. **Harness-нейтрален.** В инструкциях нет названий инструментов и путей
   конкретного рантайма. Механика описывается в терминах задачи («бриф»,
   «гейт», «отчёт»), а не API конкретного агента.
2. **Проект-нейтрален.** Нет зависимости от одного репозитория, клиента или
   аккаунта. Конкретный проект может быть указан как источник правила, но не
   как условие работы.
3. **Не воспроизводится из модели.** Внутри — решения, пороги, команды
   проверки, грабли. Пересказ общих знаний модели не нужен: она их знает.
4. **Проверен.** Есть след применения: прогоны, тесты, разборы. Навык,
   написанный «на будущее», не хранится.
5. **Операционален.** Императивные правила, которые можно проверить командой
   или замером. Объяснения — одна строка «почему», не эссе.

Всё, что не проходит хотя бы один пункт, в ядро не попадает: остаётся в личной
библиотеке автора или в самом проекте.

## Формат навыка

```markdown
---
name: <имя каталога>
description: "Открывать, когда <триггер>."
version: 1.0.0
author: fhfqndj
license: MIT
platforms: [linux, macos, windows]
metadata:
  tags: [<область>, <ещё-область>]
  related_skills: [<связанный-навык>]
---

# <Заголовок: что решает>

<1–3 строки: что внутри и когда не применять.>

## Когда открывать

<Триггеры: симптомы, стадия задачи, вопросы, ради которых навык открывают.>

## <Рабочие разделы>

<Императивные правила. Команда проверки рядом с правилом.>

## Грабли

<Симптом → механизм → как делать. Одна грабля — одно место, без повторов.>
```

Жёсткие правила формата:

- **`name`** — ASCII, kebab-case, совпадает с именем каталога. Имя не
  переводится и не меняется задним числом.
- **`description`** — одно предложение, ≤60 символов, триггер в начале. По
  нему агент решает, открывать навык или нет. Шаблон:
  `Открывать, когда <триггер>.`
- **`version`** — semver. **`author`** — `fhfqndj`. **`license`** — `MIT`.
- **`metadata.tags`** и **`metadata.related_skills`** — классификация и
  связь с другими навыками; `related_skills` ссылается только на навыки
  этого репозитория.
- **Один язык на навык.** Есть русская проза — весь навык по-русски; проза
  только английская — навык остаётся английским. Код, команды, пути и цитаты
  не переводятся.
- **`SKILL.md` — рабочий минимум.** Всё, что длиннее нескольких экранов,
  уходит в `references/<тема>.md` внутри каталога навыка: файл едет вместе с
  навыком при любой установке. Отдельного `docs/` в репозитории нет.
- **Никаких абсолютных путей, имён людей, токенов и локальных конфигов.**
  Примеры путей — `<repo>`, `~/…`, относительные, а назначенные владельцем
  места — плейсхолдерами `<workspace>`, `<projects>`, `<kb>`, `<vault>`,
  `<agent-root>`.

## Схема имён

Имя навыка — идентификатор для harness, поэтому ASCII, kebab-case, 2–4 слова,
класс задачи, а не сессия и не жаргон: `git-naming`,
`delegating-to-subagents`, `skill-sourcing`, `plan`. Без сокращений и имён
проектов. Имя не переводится и не меняется задним числом: по нему ссылаются
другие навыки и `INDEX.md`.

## Уровни

`INDEX.md` помечает каждый навык уровнем:

- **L1** — авторская методология: свои решения и грабли, которых нет в общих
  знаниях.
- **L2** — проверенная общая практика с зафиксированными командами, гейтами и
  граблями.

Уровень нужен, чтобы при сжатии ядра знать, что можно сокращать: L2 сжимается
до сути, L1 — только переписывается.

## Установка в harness

Навык — каталог с `SKILL.md` (и, если есть, `references/`, `scripts/`,
`templates/`). Установка — копия этого каталога туда, где ваш harness ищет
навыки; конкретный путь зависит от harness. Требования к установке:

- копировать каталог целиком, а не один `SKILL.md`: иначе ссылки на
  `references/` станут битыми;
- не заводить локальную копию с тем же именем рядом с общей: побеждает та,
  которую harness найдёт первой, и правки в репозитории перестанут доезжать;
- ссылки-симлинки работают не везде: harness, который обходит каталоги, может
  не заходить в симлинк. Копия работает везде.

### DeepSeek Harness (DSH)

Для DSH копировать каталоги не нужно: репозиторий сам является пакетом-бандлом,
а `dsh-plugin.js` регистрирует `skills/` как bundled-провайдер. Навыки попадают
в каталог сессии любого пресета, тело грузится по запросу, настройки пресетов
не меняются.

Установка пакетом (предпочтительно):

```text
plugin_manager install_bundle target: github:vasune/skills-kit
```

Спецификация — `<owner>/<repo>` того репозитория, где лежит этот пакет: в
форке подставляется свой владелец, в upstream — только после мержа коммита с
бандлом.

После установки бандл `skills-kit` виден в списке бандлов профиля; в новой
сессии навыки репозитория появляются в каталоге рядом с навыками хоста.

Установка копией (если бандлы не нужны или DSH без менеджера плагинов):

```bash
./scripts/install.sh --target dsh          # $DSH_HOME/skills, по умолчанию ~/.dsh/skills
./scripts/install.sh --target dsh --verify
```

Проверка связки пакета (`package.json` → патч → модуль) входит в
`scripts/check.py`; версия `package.json` сверяется с `plugin.json`.

## Как добавить или поправить навык

1. Каталог `skills/<группа>/<навык>/SKILL.md`, frontmatter по формату выше.
2. Строка в `INDEX.md`: группа, уровень, когда открывать, число файлов.
   Навык без строки в каталоге для будущей сессии не существует.
3. Прогнать `python3 scripts/check.py` — до нуля ошибок.
4. Коммит по правилам `git-naming`: новый навык — `feat`, правка — `fix` или
   `docs`.

## Проверка

```bash
python3 scripts/check.py
```

Проверяет frontmatter и разрешённые ключи, совпадение `name` с каталогом,
полноту `INDEX.md` в обе стороны, битые относительные ссылки, абсолютные
пути, шаблоны секретов, мусорные файлы, двусторонность `related_skills` и
parity манифестов установки. Предупреждения не блокируют коммит; ошибки —
блокируют.

Проверку самого валидатора делать пробным «плохим» навыком: абсолютный путь,
секрет, битая ссылка. «Ошибок: 0» без этого шага ничего не значит.
