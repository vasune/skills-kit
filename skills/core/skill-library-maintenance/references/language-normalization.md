# Приведение навыков к одному языку

Правило владельца: **если в навыке есть русская проза — весь навык переписывается
по-русски; если проза только английская — навык остаётся английским.** Смысл
правила — убрать навыки, где половина разделов на одном языке, а половина на
другом; моноязычный навык не бывает «правильным на 60%».

## 1. Классифицировать по прозе, а не по алфавиту

Считать долю русских слов в тексте без блоков кода, инлайн-кода и ссылок.
Готовый инструмент — `scripts/lang_check.py` в репозитории навыков (печатает
долю русского и номера строк с английскими сериями, код возврата 1 при
нарушении).

Ловушка: **английский навык, цитирующий фразы пользователя по-русски, — не
смешанный.** «что мне вписать в .env?», «проведём ревью», «могу дать тебе
доступ к аккаунту» — это цитаты (примеры входа), их оставляют как есть, а
навык остаётся английским. Переводить 15 КБ английского текста из-за одной
цитаты — работа впустую. Признак настоящей смешанности — **русские разделы**
(заголовок и несколько абзацев), а не отдельные слова и реплики.

Порог для быстрого прохода: ниже ~15% русского — смотреть глазами, что это
(цитаты → оставить, разделы → переводить); выше — навык русский, переводим
остатки английского.

## 2. Что переводится, а что нет

| Переводить | Не трогать |
|---|---|
| прозу, заголовки, таблицы (и шапки столбцов), подписи, чек-листы | блоки кода, команды, флаги, ключи, значения YAML |
| `description` в frontmatter — форма «Открывать, когда <триггер>. <что делает>.» | `name`, `tags`, `related_skills` — это идентификаторы и ключи поиска |
| комментарии внутри код-блоков (по желанию) | пути, имена файлов, переменных, сервисов, названия компонентов |
| пояснения вокруг нормативных примеров | сами примеры формата (сообщения коммитов, версии, вывод CLI) |
| — | цитаты внешних источников: тексты лицензий, FAQ вендора, сообщения об ошибках, вывод инструментов |

Строки, где английский законен (цитата, список имён, технический термин),
помечаются в конце строки маркером `<!-- lang: allow -->`: `lang_check.py` их
пропускает, а следующий человек видит, что это решение, а не недоделка.

## 3. Порядок работы

1. `./scripts/lang_check.py` — получить список навыков с английскими сериями и
   их объём. Сразу разделить на два вида работ: **точечная правка** (1–5
   серий: правим только эти строки, файл не перечитываем целиком) и
   **перепись** (десятки серий: переводим весь файл).
2. Точечные правки делать самому: это чтение нескольких строк, делегирование
   дороже, чем работа.
3. Переписи делегировать, **один навык на задачу** и с явным списком файлов;
   в брифе — что нельзя менять (код, команды, пути, ключи YAML), какие
   английские фрагменты остаются цитатами, и приёмка =
   `./scripts/lang_check.py <навыки>` с нулём серий.
4. Проверить самому, не веря отчёту:
   - `./scripts/check.py` → 0 ошибок;
   - блоки кода против базовой ревизии: вытащить ```-блоки из рабочего дерева и
     из `git show HEAD:<файл>`, выкинуть комментарии и пустые строки, сравнить;
     расхождение = в командах что-то «переведено»;
   - объём файла в пределах ±20% и совпадение числа заголовков с оригиналом
     (признак потерянного раздела);
   - 3–5 утверждений из отчёта сверить с файлом.
5. Коммит по темам: инструмент проверки (`feat:`), переводы (`docs:`).

## 4. Грабли

- **`description` — тоже проза.** Навык, переведённый в теле, но с английским
  `description`, в списке выглядит двуязычным: правится первой строкой.
- **Не переводить `tags`/`related_skills`.** Они сверяются с именами навыков и
  поисковыми ключами; кириллица там ломает связи.
- **Чекер шумит на именах.** Список из пяти названий продуктов подряд — не
  проза; поэтому маркер, а не «переписать названия».
- **Широкий веер агентов падает на перегрузке провайдера** (HTTP 429): падают
  отдельные задачи, файлы при этом обычно не тронуты — проверить `git status`
  по этим путям и добить их самому, а не перезапускать веер.
- **Отчёт агента «готово» не значит «ноль».** Прогнать чекер и сравнение
  блоков кода самому: переведённая команда выглядит правдоподобно и ломает
  навык молча.
- **Большой файл не переписать целиком одной записью.** Если файл читался
  по частям, защита записи отказывает («was last read with offset/limit pagination») <!-- lang: allow -->
  и правка не проходит. Порядок: перевести в новый файл рядом (`SKILL.new.md`),
  затем `mv` на место и сразу сверить блоки кода с `git show HEAD:<файл>`.
- **Склейка «переведённый низ + оригинальный верх» теряет куски.** При замене
  первых N строк легко отрезать русские абзацы, стоявшие внутри английского
  раздела (так пропали абзацы про переезд плеера). Ловится не чекером, а
  сравнением с HEAD: числа (все `\d{2,}` из старой версии должны остаться) и
  число заголовков; конкретные слова проверять `grep` по 3–5 ключевым
  идентификаторам (`pendingSeek`, `readyState`).
- **Блок кода внутри цитаты (`> ```bash`) не считается кодом, если чекер ищет
  только строки, начинающиеся с ```.** Тогда английские сообщения внутри такого
  блока читаются как проза: снимать `>` перед проверкой ограждения.
- **Код-блоки сравнивать без комментариев и пустых строк** — иначе перевод
  комментария внутри блока выглядит как «перевели команду», и наоборот.
