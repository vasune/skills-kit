# Чистка каталога агента: класс задачи и правила

Каталог агента (дом хоста) — это установка CLI, его окружения, реестр активных версий
инструментов, кэши, логи, база сессий и профили. Карта конкретного хоста, что в нём живёт и
какие команды сработали, — в документации своего хоста. Цифры намеренно
не записаны: они меняются с каждым обновлением — мерить, а не запоминать.

## Порядок

1. **Инвентарь со скрытыми каталогами.** Считать `du -sh * .[a-z]*`: без скрытых каталогов
   из счёта выпадают история установки и бэкапы куратора, а это обычно самые крупные куски.
2. **Развернуть только крупное.** Второй проход — по подкаталогам установки, окружениям
   инструментов, кэшам и собранному приложению; мелкое не разбирать до того, как найдено крупное.
3. **Понять, что реально запущено и откуда.** Список процессов показывает, из какого каталога
   работает приложение и инструменты; без этого шага нельзя отличить живое от артефакта.
4. **Сверить активные версии с реестром установленного.** Каталог версии, которой нет в реестре
   активных, — остаток прошлого обновления. Удалять по имени каталога, а не по «похоже на старое».
5. **После удаления проверить живость хоста** штатной командой хоста (список — в документации своего хоста):
   приложение, гейтвей и модель должны остаться живыми.

## Что где лежит: категории и вердикты

| Категория | Что это | Вердикт |
|---|---|---|
| История установки CLI | репозиторий обновления и его служебные данные | не трогать: без неё перестанет работать обновление; сборка мусора даёт копейки |
| Окружение CLI | интерпретатор и зависимости, из которых работает агент | не трогать |
| Зависимости сборки десктопа | `node_modules` рядом с десктоп-приложением | не трогать без задачи пересобрать десктоп |
| Собранное приложение | релизная сборка десктопа, **часто именно из неё запущено приложение** | не трогать, пока список процессов показывает запуск оттуда |
| Промежуточные артефакты сборки | `build/`, `dist/` рядом с релизом | можно удалить, пересоберутся |
| Кэш упаковщика десктопа | кэш сборки приложения | удалять |
| Окружения инструментов | venv, которые создаёт установщик под extras (браузер, telegram, vision и т.п.) | **пересоздаётся само**; выигрыш только от дублей окружений |
| Реестр версий инструментов | активные версии chromium, node, python, uv, ffmpeg и пр. | активные — по реестру установленного; прочие версии удалять |
| Кэш пакетного менеджера | кэш загрузок под каталогом хоста | чистить; учитывать, что у утилиты может быть свой системный кэш — тогда проверять оба места |
| Черновики прогонов | скретч-каталог агента | чистить свободно |
| Рабочие кэши рантайма | кэш делегаций, вывода команд, exec | мелочь, не трогать |
| Логи | текущие файлы и их ротации | ротации удалять, текущие оставлять |
| Бэкапы навыков куратора | content-addressed бэкапы правок библиотеки (тысячи файлов) | прореживать по дате, если история версий навыков не нужна |
| База сессий | сессии, сообщения, поисковый индекс | оптимизировать штатным путём, не удалять файл |
| Профили | другие профили со своими сессиями и памятью | не трогать без прямой просьбы |
| Шимы инструментов | обёртки для запуска инструментов | нужны |
| Мелочь | модели, вложения, служебные состояния | не трогать |

## База сессий

База растёт от сообщений и от поискового индекса: старая раскладка хранит копии сообщений и
индексирует вывод инструментов, поэтому файл в разы больше самого текста. Штатный путь —
оптимизация хранилища: она пересобирает индекс в компактную раскладку и делает VACUUM,
разговоры не меняет, прерывание безопасно.

- Оптимизация **отказывается работать, пока базу держит другой процесс, и называет PID** —
  это не сбой, а защита: остановить гейтвей и приложение, повторить.
- Принудительный флаг не использовать: перезапись базы под живым писателем даёт битый файл
  журнала, и восстановление дороже выигранных мегабайт.
- Если владелец работает в десктоп-приложении прямо сейчас, честно сказать, что оптимизация —
  на потом, а не жать её под живой сессией.
- Статистика до/после — штатной командой хоста; она и идёт в отчёт.

## Как отчитываться

- Таблица «было → стало» по каталогам и одна итоговая строка «N ГБ → M ГБ».
- Отдельно назвать, что удалено, что удалить нельзя и почему (история установки, живое
  приложение, чужой профиль), и что требует действия владельца.
- Если каталог после удаления появился снова (самопересоздаваемые окружения), сказать об этом
  в отчёте: иначе владелец решит, что чистка не сработала.
- Обновить памятку в базе знаний, если там записан прежний размер (правила актуализации заметок-снимков — в навыке про обслуживание базы знаний, если он есть).
