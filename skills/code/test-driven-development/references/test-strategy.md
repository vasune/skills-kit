# Стратегия тестов: флаки, безопасность, нагрузка, E2E

Справочник к `test-driven-development`. Пирамида, DAMP и двойники — в `SKILL.md`; здесь четыре
режима, которые пирамида не описывает: нестабильные тесты, проверки безопасности, нагрузка и
сквозные сценарии.

## Флаки: разбирать, а не ретраить

Флак — тест, который падает не из-за кода. Ретрай до зелёного прячет причину и превращает набор в
лотерею: зелёный после ретрая не доказывает ничего.

Четыре причины и как проверить:

| Причина | Признак | Проверка |
|---|---|---|
| Порядок и общее состояние | падает в наборе, проходит в одиночку | прогнать файл отдельно и весь набор; перемешать порядок |
| Время и асинхронность | падает на медленной машине или в CI | зафиксировать время, убрать `sleep`, ждать состояние |
| Сеть и внешние сервисы | зависит от доступности | заглушка или локальный сервер, без реальной сети |
| Тестовые данные | совпадение имён или id между тестами | уникальные данные на тест, очистка после |

```bash
# повторить один тест — поймать нестабильность
for i in {1..10}; do npx vitest run tests/x.test.ts || break; done

# перемешать порядок: тест, зависящий от соседей, падает только так
npx vitest run --sequence.shuffle

# тот же вопрос для pytest
for i in {1..10}; do pytest tests/test_x.py -q || break; done
```

- **Нестабильный тест карантинится:** снять с гейта, завести задачу с владельцем и датой. Оставлять
  его красным в общем прогоне — приучать себя игнорировать красное; глушить `.skip` без срока —
  терять проверку.
- Чинить причину: ждать конкретное состояние или ответ, изолировать данные, убрать зависимость от
  текущего времени и случайности. После починки — прогон с перемешанным порядком.
- **Запрещено:** «поставим retry и посмотрим». Ретрай допустим только для внешнего нестабильного
  сервиса, который нельзя заменить заглушкой, и тогда он видим в отчёте, а не молчит.

## Безопасность как тесты, а не как чек-лист

Проверки, которые должны жить в наборе, а не в голове:

| Что | Ожидание | Пример |
|---|---|---|
| Нет / истёкший / подделанный токен | 401 | запрос к защищённому маршруту |
| Чужая роль | 403 | обычный пользователь → админ-маршрут |
| IDOR | 403/404 | чужой id в пути и в теле запроса |
| Rate limit | 429 после N попыток | 6-я попытка входа |
| Кодирование | разметка не исполняется | `<script>alert(1)</script>` в поле возвращается текстом |

Плюс ассерты на заголовки (`X-Content-Type-Options`, `X-Frame-Options`, CSP) и на инъекции:
`' OR 1=1--` в поиске не меняет результат запроса. Один тест на один отказ — как и везде.

## Нагрузка: пороги вместо «быстро»

Нагрузочный прогон — тест с числом, а не демонстрация. Минимум на k6:

```javascript
export const options = {
  stages: [
    { duration: '30s', target: 20 },
    { duration: '1m', target: 20 },
    { duration: '30s', target: 0 },
  ],
  thresholds: {
    http_req_duration: ['p(95)<500'],
    http_req_failed: ['rate<0.01'],
  },
};
```

| Тип | Когда | Что проверяет |
|---|---|---|
| load | перед выкатом | ожидаемая нагрузка: p95 и доля ошибок |
| stress | раз на проект | где ломается и как деградирует |
| spike | перед публичным запуском | короткий пик |
| soak | при подозрении на утечки | память и стабильность часами |

Порог по умолчанию для API инструмента: p95 < 500 мс и ошибок < 1%. Для локального стенда хватает
load; stress и spike — под конкретный вопрос «выдержит ли», а не «на всякий случай».

## E2E: мало и по приоритетам

- **P0** — вход, главное действие инструмента, сохранение данных.
- **P1** — выгрузка, права, повторяющиеся сценарии.
- **P2/P3** — редкие ветки; дешевле покрыть маленькими тестами, чем поднимать браузер.
- Данные: подготовка перед тестом и очистка после; вход переиспользовать (сохранённое состояние
  сессии), а не логиниться в каждом тесте. Ждать состояние, URL или ответ — не `sleep`.

## Отчёт покрытия

Отчёт — числа и гэпы, а не «тесты есть»:

- сводка: всего / прошло / упало / пропущено;
- покрытие по модулям; отдельно — гэпы (файл или строки без тестов);
- порог изменённых строк ≥ 80% — из `quality-bar`, там же команда и ратчет; lcov пишут сами тесты;
- для нагрузки — p50/p95/p99 по ключевым эндпоинтам.

Порог без команды — аспирация: число берётся из lcov и падает в гейте, а не живёт в отчёте.
