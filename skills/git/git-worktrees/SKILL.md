# Работа через git worktree

Worktree — второй рабочий каталог того же репозитория с другой веткой. История, объекты и remote общие, рабочее дерево и индекс — свои. Это дешевле клона и чище, чем переключать ветку в основном дереве.

## Когда открывать

- Параллельные агенты или потоки в одном репозитории без драки за build-каталоги.
- Сравнить поведение с предыдущим коммитом или веткой: контрольный опыт «было → стало».
- Ревьюер читает замороженное дерево, пока родитель правит рабочее.
- Долгая работа в ветке при чистом `master` (и наоборот).
- Проверка каждого коммита серии или `bisect` без переключения основного дерева.

## Порядок

1. **Куда.** Снаружи основного дерева, в видимом месте: `<agent-root>/repos/<repo>-<branch>` для агентской работы, либо рядом с репозиторием (`../<repo>-<branch>`), если владелец держит проект там. Не внутри основного дерева (иначе `git status` и сборка путаются), не `/tmp` и не `mktemp` (см. `local-work-hygiene`).
2. **Создать:**
   ```bash
   git worktree add <path> -b <branch>     # новая ветка
   git worktree add <path> <branch>        # существующая ветка
   ```
   Имя ветки — по `git-naming`.
3. **Донастроить то, что git не копирует:** `.env`, локальные конфиги, `node_modules`/`venv` (`npm ci`, `uv sync`), хуки. Игнорируемые и неотслеживаемые файлы в новый worktree не приезжают.
4. **Базовая линия до работы:** прогнать тесты или сборку и записать число. Без неё непонятно, что сломал ты, а что было сломано до.
5. **Работать:** один worktree — одна ветка. Коммиты и push — как обычно, из своего каталога; история общая, конфликтов между worktree нет.
6. **Закрыть:** `git worktree remove <path>` (нужно чистое дерево), затем `git worktree prune`; ветку удалять отдельно после merge (`git branch -d <branch>`).

## Параллельные агенты

- Каждому ребёнку — свой worktree и свой каталог сборки; в брифе — точный путь и ветка.
- Общий артефакт (контейнер, dev-сервер, порт) — только у родителя; дети поднимают своё на свободном порту.
- В общем дереве ребёнку запрещать `git worktree`, `git stash`, `git reset`, `git checkout -- .` (см. `delegating-to-subagents`).
- Слияние параллельных веток — по `merge-reconciler`, если они разошлись по одному файлу.

## Грабли

- **Одна ветка не может быть в двух worktree:** `fatal: '<branch>' is already checked out`. Для второй копии — новая ветка от той же точки.
- **Игнорируемые файлы и `.env` не копируются.** Тесты падают «не из-за кода»: сначала донастроить окружение.
- **`node_modules`/`venv` не переносить копированием** между worktree разных ОС или архитектур — ставить заново.
- **`git worktree remove` падает на грязном дереве** — разобраться, куда девать правки, а не сносить с `--force` по привычке.
- **Удалил каталог руками** — `git worktree prune`, иначе `git worktree list` врёт о живых worktree.
- **IDE и индексатор видят две копии** — не путать пути в отчётах и командах.
- **Worktree — не копия репозитория:** `fetch`, remote и ветки общие; «в другом worktree другая история» — ошибка чтения.
